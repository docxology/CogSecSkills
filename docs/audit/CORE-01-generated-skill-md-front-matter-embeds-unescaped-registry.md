# CORE-01: Generated SKILL.md front matter embeds unescaped registry summary, producing invalid YAML for entries whose summary contains ': '

|Field|Value|
|---|---|
|Audit ID|`CORE-01`|
|Lens|`CORE`|
|Severity|`medium`|
|Red-team verdict|`VALID`|
|Status|Open (validated 2026-09-10)|
|Tracking|[GitHub issue](https://github.com/docxology/CogSecSkills/issues/6)|

## Summary
The SKILL.md generator interpolates the registry summary into YAML front matter with a plain f-string, so any skill whose summary contains `: ` ships front matter that no YAML parser can read (a plain scalar cannot contain `: `). At least three shipped skills — `sat.getting_started_checklist`, `sat.indicators_validation`, and `critical_review.project_critical_review` — are affected. The repo's own drift gates never catch this because they compare the generated bytes against output regenerated by the same f-string, making the defect self-consistent and invisible.

## Evidence
`src/cogsecskills/authoring/author.py:405` in `_skill_md`:

```python
f"description: {entry.summary}\n"
```

The same pattern exists at `src/cogsecskills/authoring/scaffold.py:171`. Real registry data at `registry/skills.yaml:15`:

```yaml
summary: "Frame an analytic task: question, drivers, assumptions, and prior judgments before diving in."
```

And the generated file on disk, `skills/sat/getting_started_checklist/SKILL.md:3`, contains the invalid plain scalar:

```yaml
description: Frame an analytic task: question, drivers, assumptions, and prior judgments before diving in.
```

The red-team verifier confirmed both cited lines verbatim, confirmed the on-disk front matter is unparseable YAML, and found no mitigation: nothing in `src/cogsecskills` parses SKILL.md front matter as YAML — it is only read textually (`authoring/definitions.py:158`) and drift-checked byte-for-byte (`authoring/definitions.py:489`, `artifacts/manuscript_assets/assets_io.py:60`) against output regenerated by the same f-string. `skill.yaml` is separately generated via `yaml.safe_dump` and is fine.

## Impact
SKILL.md front matter exists for external harness consumption; any tool that parses it as YAML fails or misparses on 3+ of the 100 shipped skills. The repo's own tooling never detects this because the drift checks regenerate the same malformed bytes, so the defect can persist indefinitely and new summaries containing `: ` will silently widen it.

## Remediation
In both `author.py:_skill_md` (line 405) and `scaffold.py:_skill_md` (line 171), replace the f-string interpolation with proper YAML serialization of the header — e.g. `yaml.safe_dump({'name': entry.id, 'description': entry.summary}, sort_keys=False)` — or wrap the summary in double quotes with escaping. The codebase's own `_skill_yaml` already uses `yaml.safe_dump`, so this matches existing practice. Update the byte-level drift-check fixtures for the affected skills after regenerating.
